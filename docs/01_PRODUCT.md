# 01. 제품 명세와 사용자 경험

문서 버전 3.0 | 기준일 2026-09-13 | 상태: 국내 서비스 설계 확정, 지도·장소 데이터 전환 전

## 1. 제품 정의

**LiveToEat은 내가 저장한 맛집 지도를 만들고, 다른 사람의 맛집 지도를 구경하며, 필요한 지역만 공유하는 서비스다.**

첫 제품은 국내 음식점, 카페, 베이커리와 식음료 장소를 담는 iOS/Android 앱이다. 2026-09-12 사용자 결정으로 서비스 범위를 국내로 변경했다. 기존 한국어/영어 UI와 확장 가능한 지역 구조는 유지하며, 해외 장소 검색과 해외 출시 검증은 첫 출시 필수 범위에서 제외한다.

2026-09-13 사용자 결정으로 **네이버 Maps + 공공데이터 기반 자체 장소 DB**를 확정했다. 지도는 네이버가 표시하고, 장소 검색·상세·저장은 자체 DB와 자체 장소 ID를 기준으로 처리한다. 기본 자료는 소상공인시장진흥공단 상가(상권)정보이며, 인허가 자료는 검증 후 보완한다. 네이버/카카오 검색은 필수 의존성이 아닌 보조 후보로 둔다. 데이터 처리와 갱신 계약은 [03 문서](03_MAPS_AND_IMPORT.md), 구현 전환 상태와 검증 순서는 [04 문서](04_DEVELOPMENT.md)를 따른다. 설계 확정은 실제 연동 완료를 뜻하지 않는다.

핵심 흐름:

```text
장소 검색
→ 내 지도에 비공개 저장
→ 다른 사람의 공개 지도 탐색
→ 마음에 드는 곳을 내 지도에 저장
→ 국내 지역 선택
→ 공유할 장소 확인
→ 링크 전송
→ 상대방이 앱 또는 웹에서 열람
```

## 2. 첫 출시 필수 범위

P0는 출시 전 반드시 구현한다. P0-S는 P0를 가능하게 하는 사전 기술 검증이다. P1은 첫 출시가 없어도 되는 기능으로 숨기며 준비 중 버튼으로 화면을 채우지 않는다.

| ID | P0 요구사항 | 완료 조건 |
|---|---|---|
| R01 | 개인 지도와 목록 | 내 저장만 표시하고 앱 종료/재로그인 후 유지한다. 장소 개수와 지도 표시 가능 개수를 구분한다. |
| R02 | 국내 장소 검색 | 공공데이터 기반 자체 DB에서 상호/지역으로 검색하고 지점과 주소를 확인한 후 저장한다. 검색 누락·중복·좌표 품질을 표본 검증하고 자료 기준일과 정보 확인 필요 상태를 표시한다. |
| R03 | 저장 편집 | 삭제, 가고 싶은 곳/방문한 곳, 개인 메모, 태그, 추천 표시가 동작한다. |
| R04 | 사람 중심 둘러보기 | 지역을 선택하면 해당 지역에 공개 저장이 있는 사람과 지도만 보여준다. |
| R05 | 다른 사람 지도 | 공개 닉네임/소개/허용 장소와 공개 개수만 보여준다. 비공개 총수는 노출하지 않는다. |
| R06 | 내 지도로 재저장 | 한 사람당 같은 장소는 하나다. 출처의 개인 메모/방문 기록/공개 설명을 복제하지 않는다. |
| R07 | 국내 지역 필터 | 국내 지역의 하위 지역 포함, 지역 미분류, 지도 범위 검색을 구분한다. 국가와 가변 깊이 지역 구조는 유지한다. |
| R08 | 지역 공유 | 선택한 지역의 장소를 확인하고 선택해 공유한다. 공유 화면에서 허용 범위를 임의로 넓힐 수 없다. |
| R09 | 공개범위 | private / unlisted / public과 공개 지도 활성 여부를 구분한다. 기본은 private다. |
| R10 | 공유 수명 | 만료/철회/재발급, 장소 비공개 전환/삭제, 계정 정지/탈퇴를 다음 권한 검사에 반영한다. |
| R11 | 앱 없는 사람의 열람 | 공개/공유 링크는 모바일 웹에서도 지도와 목록으로 열린다. 앱 설치를 강제하지 않는다. |
| R12 | 로그인과 계정 | 이메일 회원가입·확인·로그인·비밀번호 복구, Google 로그인, iOS Apple 로그인, 계정 연결/복구 안내, 로그아웃/탈퇴가 동작한다. Apple로 가입한 사용자의 Android 접근 경로도 검증한다. |
| R16 | 내 데이터 내보내기 | 본인 기록과 자체 장소 ID를 JSON/CSV로 제공하고 개인 메모 포함 여부를 안내한다. 함께 제공하는 공공 장소 필드는 출처·기준일·이용 조건을 명시하며 타인 개인 기록과 비밀값은 제외한다. |
| R17 | 오류/위치/접근성 | 위치 권한 없이 이용 가능하다. 네트워크 실패, 지도 오류, 키보드, 스크린리더에서도 핵심 흐름을 완료한다. |
| R18 | 신고/차단/운영 | 공개 설명과 사용자 신고, 차단, 운영자 숨김, 문의 경로가 실제로 작동한다. |
| R19 | 언어와 지역 표시 | 한국어/영어, Unicode, 국내 지역명과 날짜/시간 표시를 검증한다. 해외 지역 및 날짜변경선 지도 검증은 첫 출시 범위에서 제외한다. |
| R20 | 실제 스토어 출시 | TestFlight와 Play 테스트를 거쳐 심사/공개 배포까지 수행한다. 제출과 승인은 별도 상태로 기록한다. |

## 3. 화면 구조

하단 탭은 `내 지도 / 둘러보기 / 프로필` 세 개다. `+ 저장`은 공통 액션으로 제공한다. 처음부터 피드, 채팅, 예약, 결제 탭을 만들지 않는다.

| 화면 | 핵심 구성 | 상태/주의 |
|---|---|---|
| 내 지도 | 네이버 지도, 목록 bottom sheet, 국내 지역 칩, 방문 상태, 개인 폴더, + 저장 | 타인 핀이 섞이지 않는다. 미분류/좌표 확인 필요 항목을 별도로 찾을 수 있다. |
| 저장 추가 | 장소 검색 | 검색어 입력 후 요청한다. 클립보드를 몰래 읽지 않는다. |
| 장소 확인 | 자료 기준일의 장소명/주소, 출처·갱신 안내, 지도, 내 메모, 태그, 방문 상태, 지역 | 동명이점/이전/폐업/정보 확인 필요를 구분하고 실시간 영업 정보처럼 표시하지 않는다. 확인 전 자동 저장하지 않는다. |
| 둘러보기 | 지역 선택, 사용자 검색, 공개 지도 카드 | 가짜 팔로워나 AI 취향 점수 없이 관련 지역과 최근 업데이트로 정렬한다. |
| 상대방 지도 | 작성자, 선택 지역, 공개 핀/목록, 내 지도에 저장 | `저장됨`은 방문 인증이나 추천을 뜻하지 않는다. |
| 공유 만들기 | 지역 → 장소 선택 → 외부 표시 미리보기 → 공개범위 확인 → 만료 → 링크 | 목록/폴더 이름, 개인 메모, 방문 날짜를 자동 공개하지 않는다. |
| 공유 열람 | 허용 장소 지도/목록, 작성자 표시 허용 시 닉네임, 앱 열기 | 앱이 없으면 동일 권한의 웹 화면. 만료/철회는 공통 안내. |
| 프로필/설정 | 내 공개 지도, 개인 폴더, 공유 관리, 언어, 내보내기, 차단, 문의, 탈퇴 | 소셜 로그인 이름/사진을 공개 프로필로 자동 복제하지 않는다. |

검색은 `전국`과 `선택 지역 내`를 명시적으로 구분한다. 서울에서 앱을 켰어도 전국 검색으로 부산 상호를 찾을 수 있어야 한다. 기본 지도 중심은 마지막 선택 지역, 없으면 사용자가 고른 국내 지역이다. 첫 실행에 정밀 위치 권한을 요구하지 않는다. 검색 결과가 없으면 검색어·지역 변경을 안내하고, 없는 가게를 찾았다고 표시하거나 비슷한 지점에 자동 연결하지 않는다.

## 4. 저장 모델의 사용자 의미

`장소`는 자체 ID로 식별하는 특정 음식점 지점이다. `저장`은 사용자가 그 장소를 담은 기록이다. `개인 폴더`는 자기 저장을 묶는 분류다. 폴더 삭제는 저장 삭제가 아니다. 원본 자료의 갱신·상호 변경·폐업으로 사용자 저장과 메모를 삭제하지 않는다. 장소 병합으로 개인 기록이 충돌하면 사용자가 확인할 수 있게 보존한다.

기본값은 `want`, `is_recommended=false`, `private`. `visited`는 본인이 표시한 방문 기록이지 검증 배지가 아니다. 추천은 visited일 때만 켤 수 있다.

개인 메모, 태그, 방문 날짜, 가져온 원문, 원본 URL, 개인 폴더명은 항상 소유자 전용이다. 공개 설명은 별도 plain text 필드이며 280자 이하다. 공개 방문 상태는 별도 선택에 동의한 경우만 표시하며 P0 기본은 표시하지 않는다.

다른 사람 지도의 장소를 저장하면 내 기록은 private/want로 생성된다. 그 장소에 대한 독립적인 내 기록이므로 원작자가 나중에 공유를 철회해도 내 저장은 삭제하지 않는다. 다만 접근 불가해진 원작자 정보와 출처 링크는 숨긴다.

## 5. 공개범위와 지역 공유

| 저장 공개범위 | 내 지도 | 둘러보기/공개 지도 | 선택된 활성 공유 링크 |
|---|---:|---:|---:|
| private | 보임 | 안 보임 | 안 보임 |
| unlisted | 보임 | 안 보임 | 보임 |
| public | 보임 | 공개 지도 활성 시 보임 | 보임 |

공개 지도 비활성은 공개 검색 노출만 끈다. 별도 생성한 링크까지 자동 철회하는 것으로 설명하지 않는다. `모든 외부 공개 중단` 액션은 공개 지도 중단과 링크 일괄 철회를 함께 수행한다.

지역 공유는 지역 필터에 해당하는 **선택 시점의 저장 ID 집합**이다. 새 저장은 자동 추가하지 않는다. private 항목을 포함하려면 해당 항목을 unlisted로 바꾼다는 확인을 받고, 서버 트랜잭션에서 변경과 공유 생성을 함께 처리한다. 다른 기능이 이 확인을 대체하지 않는다.

비공개 전환/삭제한 항목은 기존 링크 항목도 제거한다. 다시 public으로 바꿔도 옛 링크에 되살아나지 않는다. 지역 수정으로 공유 지역 밖으로 나간 항목은 해당 공유에서 제거하고, 다시 돌아와도 자동 재추가하지 않는다. 추가/재공유는 별도 미리보기를 거친다.

링크는 재전달 가능한 열람 권한이다. `친구만`이라고 부르지 않는다. 이미 본 화면, 스크린샷, 상대방의 독립 저장까지 회수할 수 있다고 약속하지 않는다. 앱 백그라운드 복귀와 수동 갱신 때 권한을 재검사한다.

## 6. 국내 지역 UX와 확장 경계

```text
대한민국 → 서울 → 성동구 → 성수동
대한민국 → 부산 → 수영구 → 광안동
```

위는 UI 예시다. 정확한 분류는 출처가 있는 국내 지역 카탈로그를 따른다. 이름 문자열을 DB 키로 쓰지 않는다. 국가 코드는 KR로 제한하고 가변 깊이 구조는 유지한다. 누락된 단계는 건너뛰고 동일 이름 지역은 상위 지역으로 구분한다. 인기 생활권은 공식 행정구역과 다른 선택 항목이다. 해외 카탈로그와 검색은 향후 확장 범위다.

사용자에게 지역 분류가 없는 장소를 숨기지 않는다. `지역 미분류`에서 한번에 선택/지정할 수 있게 한다. 주소가 불완전하면 임의 국가나 좌표를 확정하지 않는다. 지역 필터와 지도 화면 범위는 별도 조건으로 표시한다.

## 7. 첫 출시에서 하지 않는 것

P1: 사람 팔로우, 공개 컬렉션 구독, 공동 편집, 사용자 사진 업로드, 푸시 알림, 확장된 내보내기 형식, 검색에 없는 장소의 직접 등록·제보, 이용 조건 확인 후 외부 검색 보조 기능.

P2: AI 취향 추천, 댓글/DM/피드, 결제/구독/광고/예약 수수료, 백그라운드 위치 추적, 오프라인 지도, 리뷰 수집, 해외 서비스.

공공자료만으로 사진·메뉴·영업시간·리뷰를 제공한다고 약속하지 않는다. 첫 출시의 장소 검색 품질은 데이터 표본과 실제 사용자 과제로 검증한다.

개인 폴더는 내 저장을 원하는 방식으로 분류하기 위해 P0로 제공한다.

## 8. 검증할 제품 가설

처음에는 개인 지도와 장소 검색만으로도 쓸 이유가 있는지 본다. 다음으로 공유를 받은 사람이 실제 장소를 보고 자기 지도에 저장하는지 확인한다. 가입 수만으로 사업 성공을 판단하지 않는다.

초기 사용성 과제는 `장소 5곳 검색·저장 → 지역별 5곳 공유 → 비회원 열람 → 앱 사용자 재저장`이다. 각 단계의 시간, 오류, 중도 포기 이유를 기록한다. 평생 무료/유료 가격은 아직 정하지 않는다. 외부 API 비용을 확인하기 전 무제한 이용을 약속하지 않는다.
