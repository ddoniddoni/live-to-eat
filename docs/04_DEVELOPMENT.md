# 04. 개발계획, 실행 지침과 진행 기록

버전 3.1 | 2026-09-13 | 단일 개발 진행 문서

## 1. 개발 원칙

LiveToEat은 React Native + Expo로 만드는 iOS/Android 앱이며, 공유 링크 열람만 작은 웹 화면으로 제공한다. npm workspaces와 루트 `package-lock.json` 하나를 사용하고, TypeScript strict·런타임 입력 검증·번역 키·제공자 DTO와 사용자 데이터 분리를 기본으로 한다.

각 작업은 관련 요구사항, 변경 파일, migration 여부, 실제 실행 명령과 검증 상태를 이 문서에 기록한다. 외부 키·계정·결제·도메인이 없어서 실행하지 못한 기능은 완료라고 쓰지 않는다. 비밀값은 소스·로그·채팅에 넣지 않는다.

2026-09-13 사용자 결정으로 **국내 서비스, 네이버 Maps, 공공데이터 기반 자체 장소 DB**를 확정했다. 앱과 공유 웹은 네이버 지도를 표시하고 검색·상세·저장은 자체 장소 UUID와 DB를 사용한다. 기본 원본은 소진공 상가정보, 인허가 자료는 검증 후 보완한다. 네이버/카카오 검색은 선택적 보조 후보이며 P0 의존성이 아니다.

현재 코드·환경변수 예시·의존성·migration은 전환 전이다. 이번에는 문서를 먼저 갱신했으며 SDK 교체, 자료 적재, DB/API 전환과 실기기 검증을 완료하지 않았다. 아래 날짜별 기록은 당시 구현·검증 이력이다. 새 설계와 충돌하는 이전 외부 API 구현은 유지할 요구사항이 아니라 후속 전환 대상이다.

## 2. 도구와 환경

로컬은 지원 Node LTS/npm, Git, Android Studio/JDK, Docker/Supabase CLI를 준비한다. iOS 로컬 빌드와 시뮬레이터는 macOS/Xcode가 필요하며, 클라우드 빌드는 실기기 확인을 대체하지 않는다.

development/preview/production은 앱 식별자, Supabase 설정, 네이버 Maps 애플리케이션/웹 도메인, EAS channel을 분리한다. 개발 앱이 production DB를 기본값으로 쓰지 않으며 지도 클라이언트 식별자와 서버·공공 API 인증 비밀을 구분한다.

| 명령 | 실제로 실행할 작업 |
|---|---|
| `npm run dev:mobile` | mobile workspace에서 Expo dev client 시작 |
| `npm run dev:share` | 작은 공유 웹 개발 서버 |
| `npm run lint` | 앱/공통/웹/서버의 해당 lint |
| `npm run typecheck` | 앱/웹/공통 타입 및 Edge 별도 타입 검사 |
| `npm run test:unit` | 도메인·컴포넌트 테스트 |
| `npm run test:db` | 로컬 Supabase의 SQL/RLS/트랜잭션 테스트 |
| `npm run test:e2e` | 준비된 실제 앱/시뮬레이터 대상 E2E |
| `npm run build:share` | 공유 웹 production bundle |
| `npm run check` | lint, typecheck, unit, 문서 참조 검사. DB/E2E는 별도 선행 환경 명시 |

기존 의존성 설치·검사 예시:

```bash
npm install
cd apps/mobile
npx expo install --check
npx expo-doctor
```

네이버 지도 래퍼는 B02에서 현재 Expo/RN 호환 버전을 검증한 뒤 exact로 설치하고 plugin과 lockfile을 함께 변경한다. 위 명령은 네이버 지도 전환을 수행하지 않는다.

개발 중에는 `npm install`, CI에서는 `npm ci`를 사용한다. Supabase CLI/EAS CLI/Firebase CLI는 devDependency 버전을 고정한다.

## 3. 환경변수와 지도 설정

아래는 **후속 구현에서 적용할 목표 환경변수 예시**다. 네이버/공공 API 변수명은 이 프로젝트의 제안 이름이며 현재 `app.config.ts`나 `.env.example`에 연결된 상태가 아니다. B02/B05에서 실제 SDK·적재 설정과 함께 확정한다.

```dotenv
APP_VARIANT=development
EXPO_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
EXPO_PUBLIC_SHARE_ORIGIN=https://example.invalid
APP_IOS_BUNDLE_ID=com.ddoni.livetoeat.dev
APP_ANDROID_PACKAGE=com.ddoni.livetoeat.dev
APP_SCHEME=live-to-eat-dev
NAVER_MAPS_CLIENT_ID=YOUR_REGISTERED_MAPS_CLIENT_ID
```

공유 웹의 목표 공개 설정은 `VITE_NAVER_MAPS_CLIENT_ID`이며 허용 웹 도메인을 등록한다. 공공 API를 사용할 경우 `PUBLIC_DATA_API_SERVICE_KEY`는 서버/운영 전용이다. CSV 기본 적재와 API 활용신청은 별개다. Supabase service role/secret, OAuth client secret, Apple .p8와 철회 토큰 암호화 키도 서버 비밀 저장소에만 둔다.

`app.config.ts`와 환경변수 검증은 새 네이버 지도 plugin, 앱 식별자, build variant에 맞춰 후속 수정한다. 현재 필수 설정을 문서 예시만 보고 제거하지 않는다. native 의존성/plugin 변경 뒤에는 새 development/preview/store binary와 공유 웹 빌드를 검증한다. [D1]

### 도움말·정책 공개 링크 설정

앱의 `apps/mobile/.env.example`에는 도움말 열람용 공개 설정을 추가했다. 실제 연락처와 문서는 소유자가 확정·게시한 뒤 연결한다. 미설정, 잘못된 URL, 해당 언어의 URL 누락은 앱에서 준비 중으로 표시하며 다른 언어로 자동 대체하지 않는다.

| 용도 | 공개 환경변수 | 표시 조건 |
|---|---|---|
| 문의 | `EXPO_PUBLIC_SUPPORT_URL`(ko), `EXPO_PUBLIC_SUPPORT_URL_EN` | 언어별 공개 HTTPS URL |
| 이용약관 | `EXPO_PUBLIC_TERMS_URL_KO`, `EXPO_PUBLIC_TERMS_URL_EN`, `EXPO_PUBLIC_TERMS_VERSION`, `EXPO_PUBLIC_TERMS_EFFECTIVE_DATE` | 해당 언어 URL + 확정 버전 + 유효한 `YYYY-MM-DD` 시행일 |
| 개인정보처리방침 | `EXPO_PUBLIC_PRIVACY_URL_KO`, `EXPO_PUBLIC_PRIVACY_URL_EN`, `EXPO_PUBLIC_PRIVACY_VERSION`, `EXPO_PUBLIC_PRIVACY_EFFECTIVE_DATE` | 해당 언어 URL + 확정 버전 + 유효한 `YYYY-MM-DD` 시행일 |

URL에는 인증 정보·세션·개인 기록을 포함하지 않는다. 개발용 예시 도메인, localhost/IP, HTTP와 사용자 정보가 포함된 URL은 열지 않는다. 앱은 표시용 버전/시행일만 읽으며, 이 설정을 인증 RPC의 동의 버전으로 자동 전환하지 않는다. 기존 인증은 `development-unpublished`를 사용하므로 B06에서 실제 법적 본문·가입 연령·동의 항목/버전 및 서버 기록을 함께 검토해야 한다. 문서를 열거나 닫아도 동의 체크나 계정 상태는 바뀌지 않는다.

정식 문서는 기존 `expo-web-browser`의 시스템 브라우저 화면에서 열고 닫기/뒤로가기로 앱에 복귀한다. 브라우저 실행 실패·잠금은 앱에서 재시도할 수 있다. 브라우저 내부의 HTTP 오류·오프라인 페이지까지 앱이 판독하는 구조는 아니며, 읽기 완료나 동의 완료로 처리하지 않는다. 페이지 가용성·정확한 본문·언어·버전·공개 접근과 반환 동작은 실제 URL 연결 시 양 플랫폼에서 다시 검증한다.

### 다음 실행 순서

2026-09-14 사용자 요청으로 Supabase·DB·API 실제 연결은 소유자가 시간을 낼 때까지 보류한다. 현재는 B06 인증 클라이언트 검토와 B15 탈퇴·신고 화면을 먼저 구현·검증하며, 아래 연동 순서는 연결 작업을 재개할 때 적용한다.

1. B02에서 수도권·광역시·지방·제주의 음식점/카페/베이커리 표본을 선정하고 검색 누락·중복·좌표·신규/폐업 반영을 측정한다. 표본·분모·허용 기준을 먼저 기록한다.
2. B02에서 현재 Expo/RN의 네이버 지도 래퍼를 검증하고 iOS/Android/공유 웹의 타일·마커·클러스터·선택·위치 거절·로고·호출 계측 결과를 남긴다. 실패하면 데이터 보완 또는 앱 연결 방식을 재검토한다.
3. B05에서 자체 장소/출처 모델, 검증 후 반영하는 적재와 갱신, 기존 저장의 안전한 연결을 구현한다. 잘못된 매칭·누락·재실행·실패 복구를 검증한다.
4. B07/B08/B12/B14에서 자체 DB 검색·상세·내 지도·타인 재저장·공유 웹을 연결하고 이전 외부 API 의존성·설정·계약을 정리한다. B13의 서버 공유 권한은 계속 별도로 검증한다.
5. B15/B16에서 출처 포함 내보내기, 데이터 갱신 운영, 비용·개인정보·접근성을 검증한 뒤 M6로 진행한다.

네이버 지도·자체 장소 DB의 실제 연동과 자료 적재는 위 순서의 후속 작업이다. 2026-09-13 문서 변경 후 사용자가 기존 미커밋 구현 전체의 커밋·푸시와 develop 통합도 요청했다. Git 반영을 새 연동 완료, 운영 환경 변경 또는 유료 서비스 가입 승인으로 해석하지 않는다.

1번의 지역 트리는 장소에 포함된 안정적인 지역 ID/경로로 구성한다. 체험용 국내 지역·장소는 명시적인 예시이며 전국 행정구역 카탈로그나 실제 검색 품질을 보증하지 않는다. 기존 저장의 지역 단계가 다르거나 해외 장소가 남아 있어도 ID·메모·폴더·공유 스냅샷을 재분류/삭제하지 않는다. 실제 검색·둘러보기의 지역 ID 계약과 공식 카탈로그는 B05/B07 연동 시 연결한다.

### 추가 고도화 1 — 화면 설정 복원 (2026-09-18)

기존 네 작업 이후 사용자가 요청한 첫 추가 작업이다. 내 지도 지역·방문 상태·개인 폴더·지도/목록 보기·정렬과 둘러보기 지역을 탭 이동 및 앱 재실행 후 복원한다. 상태는 기기에 저장하며 서버 동기화와 별개다. 상태: **ANDROID_VERIFIED** — 아래 날짜별 검증 기록 참고.

- 체험 모드와 로그인 계정의 저장 공간을 분리한다. 인증 컨트롤러가 기존 세션의 계정 ID를 화면 설정 구분에 전달하고, 계정이 바뀌면 앱 화면과 노트북을 새로 마운트한다. 이 ID를 서버 권한 검사의 대체로 사용하지 않는다. 로그아웃 후 같은 계정으로 돌아오면 자신의 보기 설정을 다시 사용할 수 있다.
- 버전 1의 작은 별도 파일/Web 저장 키에 선택 ID와 열거값 여섯 개만 저장한다. 기존 장소·메모·폴더 원본 파일과 분리하며 검색어, 작성 중 초안, 지도 중심/확대율, 마지막 탭, 토큰·이메일은 복원하지 않는다. 앱 데이터 삭제·재설치·다른 기기까지 유지하는 기능이 아니다.
- 기록을 불러온 뒤 삭제된 폴더와 없어진 지역을 전체로 되돌린다. 서버의 장소 목록이 일부 페이지만 로드된 경우에는 지역이 안 보인다는 이유로 선택을 버리지 않는다. 손상된 설정/알 수 없는 버전은 기본값으로 열고, 실제 개인 기록을 변경하지 않는다.
- 읽기 실패 때는 기존 설정 파일을 덮어쓰지 않고 기본 화면을 사용할 수 있게 한다. 읽기/쓰기 실패를 안내하고 재시도를 제공한다. 쓰기 실패 시 현재 선택은 유지하며 새 선택과 늦게 끝난 쓰기가 서로 덮어쓰지 않도록 순서를 보장한다.

자동 화면 검사는 예시 데이터와 별도 QA 앱에서 `.maestro-preferences/restore.yaml` → `.maestro-preferences/deleted-folder.yaml` 순서로 **개별 실행**한다. 첫 흐름은 탭 이동·프로세스 종료/재실행·검색어 미보관을 검사한다. 두 번째는 QA의 `coffee` 예시 폴더를 삭제하고 전체 폴더 복귀·필터 초기화·재실행을 검사한다. 이후 재실행에는 QA 설치의 기본 예시 폴더를 복원해야 하므로 일반 `.maestro` 묶음과 분리했다. 개인 앱에 적용하거나 자동으로 사용자 데이터를 지우지 않는다.

### 추가 고도화 2 — 500개 기록의 목록 성능 (2026-09-18)

상태: **ANDROID_VERIFIED** — 합성 개인 기록 500개·공개 후보 장소 500개·공개 지도 작성자 500명으로 검증했다. 서버/지도 연결을 보류한 상태에서 목록·검색·필터 계산과 네이티브 목록 렌더링을 개선하는 범위다.

- 내 지도는 이름·태그·개인 메모 검색 문자열과 이름순 인덱스를 기록/언어 변경 때 구성한다. 검색 입력과 지역·방문·폴더 선택마다 같은 문자열을 다시 만들거나 정렬하지 않는다. 원본 기록의 순서·객체와 전체 검색 결과를 보존한다.
- 둘러보기 작성자와 공개 지도 장소를 `FlatList`로 전환하고 보이는 범위 주변만 렌더링한다. 개인/공개 카드의 메모이제이션과 안정적인 선택 콜백을 적용했다. 큰 글씨로 높이가 달라지는 카드를 고정 높이로 가정하지 않으며, 스크롤 바깥 기록도 검색·저장할 수 있다.
- 체험 공개 장소 수는 지역별 ID 집합을 한 번 만든 뒤 작성자의 공개 선택과 대조한다. 공개 화면에는 개인 메모를 표시하지 않고, 재저장은 기존 비공개 복사 규칙을 유지한다. 실제 서버 페이지 크기·검색 계약과 지도 마커는 변경하지 않았다.

재현 가능한 계산 검사는 Node 24.20.0과 설치된 의존성으로 저장소 루트에서 실행한다. 생성기는 명시한 임시 경로에 합성 JSON만 쓰며 앱/개인 저장소에 설치하지 않는다. p50/p95는 60회 준비 실행 후 600회 측정한 **Node 계산 시간**으로, 휴대폰 입력 지연이나 FPS가 아니다.

```bash
node scripts/mobile-performance-fixtures.mjs /private/tmp/livetoeat-list-fixtures
node node_modules/rolldown/bin/cli.mjs scripts/benchmark-mobile-lists.ts --file /private/tmp/livetoeat-list-benchmark.mjs --format esm --platform node
node /private/tmp/livetoeat-list-benchmark.mjs /private/tmp/livetoeat-list-fixtures
```

네이티브 `.maestro-performance/large-lists.yaml`과 `large-text.yaml`은 일반 `.maestro`와 분리했다. 별도 체험 QA 설치에 생성된 `notebook.json`을 예시 저장 파일로 넣고, 임시 QA 소스에서만 `demoCatalog`/`demoPeople`을 `discovery.json`의 `catalog`/`people`로 교체한 뒤 실행한다. 기본 필터·한국어에서 `large-lists.yaml`, 시스템 글씨 200%에서 `large-text.yaml` 순서로 실행하며 이미 복사한 항목의 재검사에는 QA 합성 원본을 복원한다. 개인 앱에 적용하지 않는다. 검사 후 소스 교체·임시 JSON·QA 자료·글씨 크기를 복원하고 정상 예시로 기존 흐름을 재검증한다. 합성 500개 자료나 QA 전환 스위치를 배포 번들에 포함하지 않는다.

### 모바일 사용성 자동 검사 실행

`apps/mobile/.maestro`의 네 흐름은 예시 장소 저장·재편집·지역 선택·공유 초안 생성, 프로필 입력 포커스·작성 유지/버리기, 신고 사유 유지·검토에서 돌아오기·작성 버리기, 한영 도움말·문의·정책 안내 열람을 검사한다. Android에서는 소프트 키보드가 열린 상태의 첫 뒤로가기, 공유·신고의 이전 단계 이동, 확인창 취소, 프로필 탭에서 내 지도로 돌아오기도 확인한다. 실제 계정/서버를 사용하지 않는다.

- [Maestro CLI 설치](https://docs.maestro.dev/maestro-cli/how-to-install-maestro-cli)와 Android 에뮬레이터 또는 iOS 시뮬레이터가 필요하다. `EXPO_PUBLIC_AUTH_PREVIEW=true`로 실행한 별도 QA 앱을 먼저 열고 Expo 개발 메뉴를 닫는다. 자동 메뉴 표시·플로팅 버튼도 테스트를 가리지 않도록 끈다.
- 개인 기록이 없는 QA 설치에서 기본 예시 6곳으로 시작한다. 검사는 파도 커피와 공유 초안을 추가하며 앱 데이터를 자동 삭제하지 않는다. 다시 실행하려면 QA 설치만 초기화한다. 실제 개발 계정이나 개인 기록이 있는 앱을 대상으로 지정하지 않는다.
- 저장소 루트에서 `npm run test:e2e -- --device <기기 ID> -e APP_ID=<QA 앱 식별자> --test-output-dir=<임시 결과 경로>`를 실행한다. 연결 기기와 앱 식별자는 명시적으로 지정한다. 개별 흐름은 `maestro --device <기기 ID> test -e APP_ID=<QA 앱 식별자> apps/mobile/.maestro/draft-navigation.yaml`처럼 실행한다.
- 한국어 UI를 기준으로 하며 키보드 입력값은 합성 영문이다. Android는 하드웨어 키보드 연결 시에도 화면 키보드를 표시하는 설정을 켠다. 큰 글씨 검사는 QA 에뮬레이터의 글꼴 배율을 2.0으로 설정해 다시 실행하고 캡처를 확인한다. 이 검사가 한국어 IME 조합·실제 스크린리더 음성·iOS 네이티브 검증을 대신하지는 않는다.

### 도움말·정책 자동 검사 실행

도움말의 기본 검사는 `.maestro/help-navigation.yaml`이며 지원/정책 URL이 모두 비어 있는 QA 설정에서 실행한다. `.maestro-auth/help-return.yaml`은 별도 인증 폼 검사다. `EXPO_PUBLIC_AUTH_PREVIEW=false`와 예시 Supabase URL/키로 로그인 화면을 연 뒤 실행하며, 합성 이메일·비밀번호를 입력하고 문서 열람 전후 값이 유지되는지만 확인한다. 로그인·가입 제출은 하지 않는다. 체험용 `.maestro` 전체 실행에 인증 폼 검사를 섞지 않는다.

현재 설치된 Expo 57.0.21의 개발용 `expo/virtual/env` 변환은 `.env.local` 값을 별도로 합성해 명령행의 공개 변수를 덮어쓸 수 있다. 이 환경에서 `EXPO_NO_DOTENV=1`만으로 체험 모드를 바꾸면 테스트 전제가 달라진다. 사용자 환경 파일을 변경하지 않고 인증 폼/외부 링크 QA를 실행하려면 명시적인 비밀값 없는 환경으로 `npx expo start --dev-client --no-dev --minify --clear --port 8082`를 시작하고 QA 앱을 해당 개발 링크로 다시 연다. 환경값을 바꿀 때는 이전 변환 캐시도 갱신한다. 이 실행 모드는 `__DEV__`가 필요한 3번 모의 실패 주입용 실행과 구분한다.

### 실패·재시도 자동 검사 실행

일반 `.maestro` 흐름과 별도로 `apps/mobile/.maestro-failures/recovery.yaml`을 실행한다. 앞 절처럼 개인 기록이 없는 별도 QA 앱 식별자를 사용한다. 개발 서버에 `EXPO_PUBLIC_AUTH_PREVIEW=true`와 다음 값을 함께 지정한다.

```dotenv
EXPO_PUBLIC_DEMO_FAILURE_PLAN=load:offline,search:offline,search:timeout,search:slow,save:storage,save:slow,share:timeout,share:slow
```

```bash
maestro --device <기기 ID> test -e APP_ID=<QA 앱 식별자> --test-output-dir=<임시 결과 경로> apps/mobile/.maestro-failures/recovery.yaml
```

- `load/search/save/share/settings` 작업별로 같은 이름의 항목을 순서대로 한 번씩 소비한다. `offline/timeout/storage`는 실제 요청·파일 쓰기 **전에** 모의 실패를 발생시키고, `slow`는 2.5초 기다린다. 통신·기기 설정이나 서버를 변경하지 않는다. `__DEV__`와 명시적인 체험 모드가 모두 참일 때만 활성화한다.
- 재실행은 QA 앱만 종료·초기화하고 다시 열어 기본 예시 6곳과 새 요청 시나리오로 시작한다. 이 흐름은 장소 한 곳과 공유 초안 한 개를 추가한다. 정상 흐름 검사 전에는 실패 계획을 제거하고 개발 서버/앱을 재시작한다.
- 실제 읽기 대기는 12초 후 끝내고 새 조회를 허용한다. 늦은 응답은 무시한다. 쓰기는 완료 결과를 받기 전에는 다시 보내지 않는다. 클라이언트 대기 중단을 서버 쓰기 취소로 간주하지 않으며, 실제 서버의 결과 불명·멱등키·충돌 조정·오프라인 동기화는 연동 시 검증한다.

## 5. 검증 규칙

일반적으로 작업 전후에 관련 lint/typecheck/unit을 실행하고, DB 변경은 로컬 SQL 테스트, native 변경은 해당 플랫폼 빌드에서 검증한다. 다만 사용자가 해당 작업의 검증 실행을 명시적으로 보류하라고 하면 실행하지 않고 미실행으로 기록한다.

DB migration은 이미 적용한 역사 migration을 수정하지 않는다. 제거·계약 축소는 새 migration에서 수행하고, 로컬 reset부터 clean apply와 소유권/RLS를 검증한다. 이전 앱 버전과의 호환을 고려해 expand→migrate→contract 순서를 따른다.

작업 기록 형식:

```text
작업: Bxx / 관련 Rxx
변경: 경로와 주요 변경
실행: 실제 실행한 명령/플랫폼/환경
검증: 성공/실패/미실행과 증거 위치
정책/비용: 변경 유무
남은 것: blocker와 다음 작업
```
