# 03. 네이버 지도, 자체 장소 검색과 공공데이터

버전 3.0 | 기준일 2026-09-13 | 상태: 설계 확정, 데이터 품질·SDK 호환성 검증 및 구현 전환 전

## 1. 확정한 역할과 제품 경계

첫 출시는 국내 서비스다. **네이버 Maps는 지도 표시, 공공데이터 기반 자체 DB는 장소 검색·상세·저장**을 담당한다. 사용자 기록은 자체 장소 ID에 연결한다. 저장 목록을 열 때마다 외부 장소 상세 API를 호출하는 구조를 만들지 않는다.

| 영역 | 확정한 설계 | 구현/검증 상태 |
|---|---|---|
| 앱 지도 | iOS/Android 네이버 Maps SDK, `@mj-studio/react-native-naver-map` 우선 검증 | 현재 Expo 57/RN 0.86.3 조합의 호환 버전 미선정, 실기기 미검증 |
| 공유 웹 | 네이버 지도 JavaScript API + 허용된 공유 장소 DTO | UI만 구현, 실제 지도/권한 연결 전 |
| 장소 원본 | 소상공인시장진흥공단 상가(상권)정보를 적재한 자체 DB | 전체 적재·표본 품질 측정 전 |
| 보완 원본 | 행정안전부 인허가 정보 | 매칭·좌표 변환·현행 데이터셋 검증 후 도입 |
| 사용자 기록 | 자체 장소 ID와 연결한 저장·메모·방문·폴더·공개범위 | 기존 도메인/UI 존재, 새 DB 계약으로 전환 전 |
| 외부 검색 | 네이버/카카오 검색은 필요할 때 검토할 보조 후보 | P0 필수 의존성 아님, 이용 조건 확인 전 연동하지 않음 |

사용자는 자체 DB 검색 결과에서 지점을 확인하고 저장한다. 외부 목록·파일·링크 가져오기와 개인 지도 계정 동기화는 제공하지 않는다. 운영자의 공공자료 적재는 사용자용 가져오기 기능과 별개다. 검색에 없는 장소의 직접 등록·제보는 P1이며 첫 출시 검색 품질 부족을 감추는 수단으로 쓰지 않는다.

## 2. 지도 표시와 네이티브 전환

모바일 래퍼 문서는 New Architecture, Android/iOS, Expo CNG/config plugin을 지원하며 Expo Go는 지원하지 않는다고 명시한다. 현재 앱의 호환 버전과 plugin 옵션은 실제 검증 후 고정한다. 기존 지도 컴포넌트의 제공자 값만 교체하는 작업이 아니며 새 development/preview/store binary가 필요하다. [M1]

환경별 네이버 Maps 설정과 사용량을 구분하고 Android package, iOS bundle ID, 공유 웹 도메인을 등록한다. 다른 앱/도메인에서의 인증 실패도 검증한다. 공개 클라이언트 식별자와 서버 전용 비밀을 구분하며 구체적인 설정명은 선택한 SDK/콘솔의 현행 문서를 따른다.

- 내 지도에는 내 저장만 표시한다. 타인 핀은 둘러보기·상대방 지도·허용된 공유에서 표시한다.
- 좌표가 없거나 검증되지 않은 저장은 목록에 남기고 핀을 추측해 만들지 않는다.
- 현재 위치는 선택 기능이다. 위치 거절·대략 위치·지도 장애에서도 마지막 선택 국내 지역과 목록을 사용할 수 있어야 한다.
- 지도 로고·저작자 표시·고지 영역을 가리지 않는다. 공공 장소 데이터 출처는 지도 제공자 표시와 구분한다.
- 자체 장소 좌표로 마커·클러스터를 만들고 목록 선택과 연결한다. 지도 실패가 자체 검색·개인 기록 조회까지 막지 않도록 분리한다.
- 지도 타일의 자체 수집·보관과 오프라인 전체 지도는 범위 밖이다.

## 3. 장소 데이터 원본과 갱신

| 자료 | 용도 | 확인한 조건과 한계 |
|---|---|---|
| 소상공인시장진흥공단 상가(상권)정보 CSV | 음식점·카페·베이커리 기본 카탈로그 | 전국 상호·업종·지번/도로명주소·경도/위도, 무료·이용허락범위 제한 없음, 분기 갱신. 확인한 최신 파일은 2026-06-30 기준, 2026-08-05 등록. [M2] |
| 동일 기관 상가정보 API | 원본 식별자 확인과 필요한 조회 보완 | 상가업소번호 제공. CSV와의 대응·원본 ID 안정성·쿼터는 적재 전 검증. [M3] |
| 행정안전부 일반음식점 조회서비스 | 인허가일자·영업상태 보완 | 무료·이용허락범위 제한 없음. EPSG:5174 좌표를 WGS84로 변환·검증. 휴게음식점·제과점의 현행 전국 자료와 갱신 지연은 추가 확인 대상. [M4] |

원본별 식별자, 출처, 자료 기준일, 수집 시각, 원본 URL, 이용 조건·확인일을 보존한다. 서로 다른 원본의 같은 ID 문자열은 같은 장소가 아니다. 표준 장소명·주소·좌표·상태를 어느 원본에서 선택했는지도 추적한다. 공공자료의 재사용 조건을 다른 검색 서비스 응답에 확대 적용하지 않는다.

갱신 계약:

1. 공식 원본의 버전·스키마·이용 조건·좌표계·대상 업종을 확인한다. 운영 적재는 허용한 공식 URL만 사용한다. 사용자 입력 URL을 대신 가져오지 않으며 리다이렉트 대상, 파일/압축 해제 크기와 경로를 제한한다.
2. staging에 적재하고 파일 checksum, 실행 ID, 행 수와 오류 수를 기록한다. 인증키를 URL·로그에 남기지 않는다.
3. 업종, 검색용 이름/주소 정규화, 좌표 변환·범위와 원본 ID 중복을 검사한다. 원본 값과 가공 값을 구분한다.
4. 기존 원본 ID 연결을 우선 사용한다. 원본 간 연결은 지점명·주소·위치를 함께 검토하며 이름만으로 병합하지 않는다. 모호한 후보는 검토 대상으로 남긴다.
5. 추가/수정/누락 규모와 품질 기준을 확인한 뒤 검증된 자료만 반영한다. 중간 실패는 현재 서비스 자료를 훼손하지 않아야 하며 재실행은 멱등적으로 처리한다.
6. 분기 자료 공개에 맞춰 갱신을 확인하고 지연·오류를 감시한다. 마지막 성공 시각과 자료 기준일을 구분한다. 보완 API 주기는 실제 제공 주기·쿼터 확인 후 정한다.

원본에서 사라진 가게를 즉시 삭제하거나 폐업으로 단정하지 않는다. 상태는 근거·기준일과 함께 표시하고 불명확하면 정보 확인 필요로 둔다. 공공자료만으로 실시간 영업 여부·사진·메뉴·영업시간·리뷰를 확보했다고 주장하지 않는다.

자체 장소 UUID는 재적재·상호 변경으로 새로 만들지 않는다. 같은 주소의 새 업소에 이전 장소 ID를 재사용하지 않는다. 병합·이전·폐업 때도 저장과 메모를 보존하며 잘못된 병합을 되돌릴 수 있는 연결 이력을 남긴다.

## 4. 자체 검색과 저장 계약

검색은 `전국` 또는 명시한 `선택 지역 내`에서 상호/지역/업종을 조회한다. 서버는 인증·계정 상태, 검색어 길이, 지역 ID, 페이지 크기와 호출 수를 검증한다. 초기 계약은 페이지당 최대 20개와 안정적인 cursor다. 정렬은 상호·지점명 일치와 선택 지역 등 설명 가능한 기준으로 시작하고 한국어 띄어쓰기·동명이점·지점 구분을 실측한다.

```text
검색어·국내 지역 선택
→ 서버의 자체 DB 검색
→ 자체 장소 ID·상호·주소·좌표·출처·기준일
→ 사용자가 지점과 지역 확인
→ 서버가 장소 존재·상태 재검사
→ 자체 장소 ID에 내 private/want 기록 저장
```

아래는 구현할 표시 DTO이며 현재 코드의 타입을 설명하는 것은 아니다.

```ts
type PlaceSearchCandidate = {
  placeId: string; // LiveToEat 자체 UUID
  displayName: string;
  formattedAddress?: string;
  location?: { latitude: number; longitude: number }; // 검증된 WGS84
  countryCode: 'KR';
  regionIds: string[];
  status: 'operating' | 'closed' | 'unknown'; // 자료 기준, 실시간 보증 아님
  sources: { sourceKey: string; label: string; asOfDate: string }[];
  updatedAt: string;
};
```

검색·상세·내 지도·공개 지도·공유 웹은 동일 자체 DB를 읽는다. `user_id + place_id`로 중복을 막으며 클라이언트가 전달한 장소명·주소·좌표를 원본으로 신뢰하지 않는다. 자체 UUID는 열람 권한 증명이 아니므로 사용자 기록·공유 접근은 별도 검사한다. 외부 검색용 ticket이나 외부 장소 ID를 기본 저장 계약으로 요구하지 않는다.

결과가 없으면 지역·검색어 변경을 안내하고 다른 지점에 자동 연결하지 않는다. DB 장애에는 오류·재시도를 제공하고, 적재 장애에는 마지막 검증 자료로 계속 서비스한다. 기존 개인 기록은 삭제하지 않는다.

외부 검색을 추가할 때는 서비스별 저장·표시·매칭 조건을 다시 확인한다. 네이버 지역 검색은 최대 5개, 다음 페이지 없음, 별도 장소 고유 ID 없음이라는 제약이 있고 현재 확인한 API 문서만으로 영구 보관 허용 범위를 확정하지 못했다. [M5] 카카오 공식 운영진은 ID·URL 외 검색 응답의 영구 저장을 제한하며 독립 공공자료와 일시 비교 후 폐기하는 방식을 허용한다고 안내한다. [M6] 매칭 실패를 외부 응답 저장으로 우회하지 않는다. 둘 다 현재 P0 검색 원본으로 사용하지 않는다.

## 5. 비용, 보안과 장애 대응

2026-09-13 재확인한 네이버 Maps 요금은 대표 계정 1개에 월 Dynamic Map 6,000,000건 무료, 초과 건당 0.1원(VAT 별도)이다. 앱·공유 웹의 실제 과금 호출을 함께 계측하며 사용자 수나 앱 실행 수로 단순 환산하지 않는다. 계약·무료 조건은 출시 직전 재확인한다. [M7]

견적은 `max(0, 월 과금 대상 지도 호출 수 - 적용 무료 이용량) × 적용 단가 + DB·검색·적재·백업·호스팅·빌드·오류 수집 비용`이다. 자체 검색은 외부 장소 API에 건별로 의존하지 않지만 무료 운영을 뜻하지 않는다.

- 지도 사용량 알림과 앱/웹별 계측, 서버 요청/계정/IP 한도, timeout과 응답 상한을 둔다. 알림만으로 지출이 차단된다고 가정하지 않는다.
- 지도 신규 로딩, 자체 검색, 자료 갱신을 별도로 제한한다. 자동 재시도로 장애·비용을 증폭하지 않는다.
- Supabase service role, 공공 API 인증키와 선택적 서버 API secret은 서버/운영 비밀 저장소에만 둔다.
- 전체 검색어·사용자 정확한 위치·개인 메모·공유 secret·토큰을 분석/오류 로그에 넣지 않는다.
- 장기 보관 가능한 공공 장소 원본과 사용자 기록을 구분한다. 타인의 저장·공개범위는 공공데이터가 아니며 공유 철회 후 캐시로 재노출하지 않는다.

## 6. 국내 지역 모델

`region_nodes`와 `region_closure`의 국가 코드·가변 깊이 구조를 유지하고 첫 출시 검색/공유는 KR로 제한한다. 한국어/영어 표시 이름을 지원하되 행정명 문자열을 ID로 쓰지 않는다. 예: 대한민국 → 서울 → 성동구 → 성수동.

행정구역과 생활권, 지역 필터와 지도 화면 범위를 구분한다. 누락된 단계는 건너뛰고 동일 지명은 상위 지역·출처 ID로 구분한다. 해외 카탈로그·날짜변경선 검색 검증은 첫 출시 밖의 확장 작업이다.

사용자 선택 지역과 공공자료 분류 지역의 출처를 구분한다. 미분류 장소는 개인 목록에서 찾고 지정할 수 있어야 한다. 자료 갱신으로 사용자 선택을 조용히 덮어쓰지 않는다. 실제 저장 지역 수정에는 공유 범위 재검사와 벗어난 항목 제거를 적용한다.

## 7. 내 데이터 내보내기

본인 저장·자체 장소 ID·작성 기록을 JSON/CSV로 제공한다. 함께 제공하는 공공 장소명·주소·좌표에는 출처·자료 기준일·이용 조건을 담는다. 원본 추가 시 필드의 재배포 조건을 확인한다. 개인 메모 포함 여부를 설명하고 CSV 수식 주입을 막는다.

타인 개인 메모·방문 기록, OAuth 정보, 공유 secret/hash, 원본 전체 덤프와 운영 필드는 제외한다. 파일 복원 기능은 범위 밖이다. 현재 코드는 개인 기록 중심이므로 자체 장소 필드와 전체 계정 내보내기의 연결은 후속 구현·검증 대상이다.

## 8. 전환 전 필수 검증

수도권·광역시·지방·제주의 음식점/카페/베이커리 표본으로 검색 누락, 신규 가게 반영 지연, 지점 중복, 폐업·이전, 좌표 오차를 측정한다. 표본 선정 근거·분모·오류·판정 기준을 기록한다. 데이터 미확인 상태에서 전국 검색 품질을 보장하지 않는다.

현재 Expo/RN에서 양 플랫폼 타일·마커·클러스터·선택·위치 거절·로고 표시와 공유 웹 지도를 별도 검증한다. 품질이나 호환성이 미달하면 데이터 보완 또는 앱 연결 방식을 재검토하고 [04 개발계획](04_DEVELOPMENT.md)에 기록한다. 설계 선택은 확정됐지만 이 검증과 코드 전환은 아직 완료하지 않았다.
